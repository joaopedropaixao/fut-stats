# Equipe de desenvolvimento: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** criar a equipe (Orquestrador → TPL → DEVs ↔ QA) como skills, subagentes e hooks do Claude Code no repo.

**Architecture:** tudo em `.claude/`, que vai para o repo e assim chega a todos os worktrees. Hooks são scripts
`sh` pequenos (entrada JSON no stdin, `jq`), ligados no `.claude/settings.json`. Bloqueio = `exit 2` com o motivo no
stderr (o Claude lê o motivo). Os subagentes são `.claude/agents/*.md` com `model` no frontmatter. As skills são
`.claude/skills/<nome>/SKILL.md`.

**Tech Stack:** Claude Code 2.1.304 (hooks, subagentes, skills, statusLine), POSIX sh + `jq` + `osascript` (macOS),
prettier 3 já na raiz.

**Spec:** `docs/specs/2026-10-24-equipe-design.md`

## Global Constraints
- Texto para pessoas (skills, agentes, mensagens de bloqueio, docs) em português; nomes de arquivo como no spec.
- Commits em Conventional Commits, português, **sem** `Co-Authored-By` nem "Generated with".
- Nunca ler o conteúdo de um `.env` (nem para testar hooks; os testes usam caminhos falsos).
- Modelos: TPL e QA `opus`; DEVs `sonnet`.
- QA: no máximo **3** voltas. O TPL nunca faz merge.
- Hook que não consegue decidir (sem `jq`, fora de um repo git, JSON estranho) **libera** (`exit 0`): guarda nunca
  trava sessão por erro próprio.
- `pnpm lint` roda `prettier --check .`: todo arquivo novo que não seja `.md` precisa estar formatado.

## Review Focus
1. `sem-env` com falso positivo em `.env.example`, `env.ts` e `process.env.X`: deve liberar os três.
2. `sem-merge` bloqueando o merge legítimo do TPL (`git merge feature/x-back` estando em `feature/x`): deve liberar;
   só bloqueia merge com a branch atual `develop`/`main`, push para `develop`/`main` e `gh pr merge`.
3. `dev-termina-verde` em loop infinito quando o DEV não consegue consertar: depois de 3 bloqueios na mesma sessão,
   libera e o DEV reporta o que ficou vermelho.
4. `front-sem-shared` com caminho relativo ou com o arquivo em outro worktree: a branch é a do repo do **arquivo**,
   não a do `cwd` da sessão.
5. Hooks rodando na sessão do Orquestrador (checkout principal, branch `develop`) sem atrapalhar: guardas só
   bloqueiam os casos da tabela; status line sem arquivo de etapa mostra só a branch.

Cada item vira um caso no `.claude/hooks/test.sh` (Tasks 1 a 3).

## Decisão a confirmar com o dono antes da Task 1
Worktree novo precisa do `.env` da API. Proposta: `sem-env` libera **só** `cp`/`ln -s` de `.env` (copia sem mostrar
o conteúdo) quando o comando não tem pipe nem redirecionamento. Qualquer outro comando com `.env` é bloqueado.

### Task 3: Subagentes DEV back, DEV front e QA (com "DEV só termina verde")

**Files:**
- Create: `.claude/hooks/dev-termina-verde.sh`, `.claude/agents/dev-back.md`, `dev-front.md`, `qa.md`
- Modify: `.claude/hooks/test.sh`

**Interfaces:**
- Consumes: `lib.sh` (Task 1).
- Produces: subagent types `dev-back`, `dev-front`, `qa` (usados pela skill `tpl`). Relatório do DEV: seções
  `Feito`, `Testes`, `Fora`, `Dúvidas`. Relatório do QA: tabela `Cenário | Teste | Resultado | Evidência | Quem corrige`
  e linha final `VEREDITO: APROVADO` ou `VEREDITO: REPROVADO (<n> falhas)`.
- Produces: `dev-termina-verde.sh <back|front>`; checagem sobrescrevível por `DEV_CHECK_CMD` (para teste).

- [ ] **Step 1: Casos em `test.sh`:** `DEV_CHECK_CMD=true` → exit 0; `DEV_CHECK_CMD=false` → saída JSON
  `{"decision":"block","reason":...}` com o comando que falhou; 4ª chamada vermelha com o mesmo `session_id` → exit 0
  (contador em `$TMPDIR/dev-verde-<session_id>`).
- [ ] **Step 2:** rodar → falham.
- [ ] **Step 3: Implementar o script.** Checagem padrão a partir do `cwd` do JSON: back =
  `pnpm --filter @fut-stats/domain --filter @fut-stats/shared --filter @fut-stats/api run lint typecheck test`
  (em sequência, para no primeiro erro); front = `pnpm --filter @fut-stats/web run lint typecheck test`. Motivo do
  bloqueio traz as últimas 40 linhas da saída.
- [ ] **Step 4: Escrever os agentes.** Frontmatter `name`, `description`, `model` e, nos DEVs, `hooks.Stop` chamando
  `dev-termina-verde.sh back|front`. QA com `disallowedTools: Edit, Write, MultiEdit, NotebookEdit`. Corpo de cada um
  (curto, em português):
  - **dev-back:** trabalha só no worktree recebido; o contrato já está no primeiro commit (não reescreve, só
    `fix(shared): ...` quando o TPL pedir); testes conforme a tabela "Testes por tipo" do spec (domain unitário
    primeiro com bordas; API integração supertest + Postgres, permissão membro/admin/outro grupo, códigos de erro;
    nada de mock do Prisma); dono único de `schema.prisma`, `package.json` da raiz e lockfile; multi-grupo do
    `AGENTS.md`; termina deixando a API rodando e com o relatório.
  - **dev-front:** trabalha só no worktree recebido; nunca edita `packages/shared` (furo de contrato vai em
    `Dúvidas`); segue `docs/design/DESIGN.md` e as telas de entrar e rodadas; sem regra de negócio; valida no
    Playwright contra a API do back (fluxo principal, console limpo, prints em `.playwright-mcp/`).
  - **qa:** recebe spec + caminhos dos worktrees; sobe API e web; roda `pnpm lint && pnpm typecheck && pnpm test &&
    pnpm build` em cada worktree; verifica cada Given/When/Then pela API (curl) e no Playwright, com jogador, admin e
    usuário de outro grupo (login de dev `/dev/entrar`); confere a tabela de testes por tipo (unitário para regra
    nova, integração por rota com permissões e erros, Prisma sem mock, teste de reprodução para bug de volta
    anterior); não corrige nada; termina com a tabela e o veredito.
- [ ] **Step 5:** `test.sh` → `ok`. Prova real com agente descartável: criar `.claude/agents/teste-hook.md`
  (`model: haiku`, `hooks.Stop` com `DEV_CHECK_CMD=false`), rodar `claude -p "use o agente teste-hook para dizer oi"`
  e confirmar que o hook bloqueou (contador criado). Apagar o agente descartável. Se hooks no frontmatter não
  funcionarem nesta versão, mover para `SubagentStop` no `settings.json` filtrando por `agent_type` e anotar no spec.
- [ ] **Step 6: Commit** `feat(harness): subagentes dev-back, dev-front e qa`
